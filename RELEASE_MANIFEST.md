# PhaseSet public data-free release manifest

**Manifest snapshot:** 2026-08-26 (Asia/Shanghai)
**Source version:** `v0.2.1 / INTENDED_DATA_FREE_STABLE_CORE_PORTABLE_TEST_HOTFIX`
**Scientific authority:** `AUTHORITY0 / NO_REAL_DATA_RESULT / NO_CLAIM`

This manifest defines the public-safe PhaseSet source artifact. The source tree
does not self-attest external publication: only an observed immutable annotated
tag and corresponding GitHub release establish that status. This artifact is
not a dataset-rights grant, server receipt, training result, completed paper,
or submission authorization. `RELEASE_FILES.sha256` is regenerated only from
the final staged Git index and is the byte/file-set authority for the source
artifact.

## Required verification before tagging

1. Legacy and PhaseSet unit/integration tests pass on the recorded runtime.
2. Ruff and package/wheel builds pass from a clean Git-index snapshot.
3. K=2 topology is exact positive zero in value and gradient, and new full
   equals new pair-only bitwise.
4. Exhaustive K=3..6 permutation checks, deterministic parameterized
   K=8/32/128/256 streaming/allocation stress checks, K=32/128/256
   reverse-order neural-permutation checks, and separately parameterized
   padding, mixed-batch, chunk, and gradient checks pass. This is not described
   as a complete cross-product of every K and property. Runtime chunks default
   to 256 edges and canonical reductions remain fixed at 64 edges.
5. CLI and runner fail closed when rights, private manifests, server/runtime
   receipts, or predecessors are missing.
6. Staged blobs and all refs pass credential, endpoint, private-path,
   restricted-binary, data, participant-identifier, and licensing scans.
7. `RELEASE_FILES.sha256` verifies the exact Git index; its embedded copy binds
   every regular file and byte in a GitHub codeload archive.
8. `verify_wheel_against_index.py` separately requires every Python module in
   the wheel to equal its staged `src/phasepair_core` or `src/phaseset_core`
   blob byte-for-byte, rejects missing/extra modules, and binds distribution
   name/version plus the complete entry-point table to staged `pyproject.toml`.
9. After publication, `release_asset_inventory.py verify` cross-checks one
   canonical receipt against separately captured GitHub repository, release,
   annotated-tag, peeled-commit, and tree responses plus a fresh complete asset
   download. The required trusted repository ID/name/tag arguments and GitHub
   responses are external trust inputs; the receipt never authenticates itself.
   See [the exact two-phase procedure](docs/RELEASE_VERIFICATION.md).
10. The original PhasePair `v0.1.0` tag object and peeled commit are unchanged.
11. Base qualification binds all nine terminal/checkpoint rows, uses the
   three-seed integer-latency median, and reloads the three winner checkpoints
   with their frozen base logit scales. Formal consumers require an externally
   supplied expected qualification SHA-256; residual construction additionally
   requires the expected freshly rebuilt 01--08 capacity-audit SHA-256. A
   selected checkpoint proves validation-best-at-write, while the immutable
   terminal/qualification evidence proves finality. System 06 is a
   full-group/per-band
   incidence bijection using only `O(E)` integer routing metadata, and B2 has
   no complete `K x K` attention-score map.
12. Test caption fusion cannot run from sealed digest strings alone: a trusted
    host must verify and consume an external grant, and the public receipt must
    bind the returned admission plus the frozen backend manifest. The
    permutation audit establishes normalized surface stability only; semantic
    review remains provisional.
13. Formal training installs deterministic-algorithm errors, highest float32
    matmul precision, disabled TF32/reduced-precision reductions,
    deterministic cuDNN, and (for CUDA) a deterministic cuBLAS workspace. Its
    environment-v2 digest binds hardware, runtime, build, thread counts, and
    this policy; live drift fails closed and ambient flags are restored.

Exact pass counts, runtime identity, commit/tree/tag hashes, GitHub repository
ID, Actions run IDs, codeload hashes, and asset API digests are receipts and
must be inserted only after observation. Saved API bodies are not trusted merely
because they are JSON: acquisition over authenticated GitHub/TLS, the explicit
expected repository ID/name/tag, and the freshly downloaded asset bytes are
separate evidence boundaries. Empty placeholders are not verification.

## Explicitly excluded

- raw or reversible human motion, images, video, audio, captions, participant
  identities, capture membership, or private commitments;
- Embody 3D/Multi-TPC/M3Act3D/AIOZ-GDANCE/InterHuman/Inter-X samples,
  download URLs, access forms, or restricted metadata;
- SMPL-X files, CLIP or other third-party weights, private checkpoints, caches,
  runtime wheelhouses, and licensed reference PDFs;
- machine-fused sealed-test captions, prompts containing private payloads, raw
  model responses, per-sample test predictions, or recoverable identifiers;
- endpoints, usernames, host keys, credentials, tokens, secrets, private
  receipts/logs, local absolute paths, agent state, or encrypted-backup keys.

## Version boundary

- `v0.1.0`: immutable PhasePair dyadic data-free release.
- `v0.2.0-alpha.1`: PhaseSet identity, contracts, and migration pre-release.
- an externally observed annotated `v0.2.0` tag: stable data-free multi-person
  core and runner after qualification;
- an externally observed annotated `v0.2.1` tag: portable anonymous-install
  verification hotfix with unchanged model and scientific contracts;
- `v1.0.0`: real experimental aggregate, compliant paper, and complete public
  provenance, only if every external and scientific gate is genuinely closed.

Negative results do not block a release when accurately represented. Missing
rights, fabricated evidence, leaked restricted material, or an unsealed test
does block it.
